# 循环调谐器

## 关于循环调谐器

循环调谐器是一款针对 PCM 格式 (.WAV 或 Ogg Vorbis 等) 的文件，

- 设置没有接缝 (无缝) 的循环，或按条件进行跳转 (更改播放位置) 的“**链接**”
- 在播放到达特定位置时，在吉里吉里上产生事件的“**标签**”

生成这类信息的工具。



生成的信息会成为在 PCM 格式文件名末尾加上 .sli 的文件名 (例如，se001.wav 对应 se001.wav.sli)，在使用 [WaveSoundBuffer 类](../reference/WaveSoundBuffer.md) 打开 PCM 格式的文件时会被自动读取。

## 什么是无缝循环

即使不使用循环调谐器，只要使用 [WaveSoundBuffer.looping](../reference/WaveSoundBuffer.md#looping) 属性，也可以进行循环播放。但是，这种方式只能进行从声音开头播放、播放到最后再回到开头的简单循环。

使用循环调谐器，则可以像下图那样，设置在声音播放到任意位置后返回任意位置的循环。它可用于让弱起乐曲循环，或者像引擎的启动~引擎声的循环那样，无法从声音的开头重复播放的情况。



![](../_assets/lt_seamless_loop.png)



在这种情况下，如果不严格调整进行重复的时机，就会在循环位置产生“咔嗒”“噼啪”之类的爆裂噪声。循环调谐器具备辅助详细调整这一时机的功能，因此可以轻松地进行调整，实现无缝 (没有接缝) 的循环。

另外，偶尔也会出现无论怎样调整都无法去除这种噪声的情况，循环调谐器还具备通过在链接紧附近进行非常短的 (约 50ms) 交叉淡化来减轻这种噪声的功能。

## 条件链接

在“乐曲正在循环播放，但希望达到某个条件后跳出循环、进入下一段旋律”这样的场合，可以使用条件链接。

循环调谐器中，把用于更改声音播放位置的信息称为“链接”，而可以给这种链接附加条件。

循环调谐器可以管理 16 个“标志”，这些标志具有 0 ~ 9999 的值。可以对任意链接进行这样的设置：当“第 ○○ 号标志为 ○○”“第 ○○ 号标志不为 ○○”“第 ○○ 号标志小于等于 ○○”等“条件”成立时，就沿链接跳转。

标志不仅可以在循环调谐器上更改值进行测试，还可以使用 [WaveSoundBuffer.flags 属性](../reference/WaveSoundBuffer.md#flags) 从脚本进行操作。

## 标签

为了“当播放位置到达特定位置时产生事件”这样的用途，可以设置“标签”。

通过标签时，会触发 [WaveSoundBuffer.onLabel](../reference/WaveSoundBuffer.md#onlabel) 事件。事件的参数中会传入标签名，因此可以知道通过了哪个标签。



另外，通过给标签设置特殊的“**表达式**”，可以在通过标签时增减标志的值或设置值。

与上述“条件链接”组合使用，可以实现仅播放特定区间 4 次之类的用法。

## 链接、标签与缓冲

吉里吉里的 WaveSoundBuffer 始终对声音进行缓冲。解码 (从文件读取、压缩音乐文件的解压) 之后，并不是立即播放，而是先累积到称为缓冲区的内存中再播放。

也就是说，解码总是先于实际播放位置进行，在标准设置下最多会有 2 秒的偏差。

链接的条件是在这个解码的时间点被测试的，因此即使操作标志，其效果实际产生也是在最多 2 秒之后。也就是说，播放中在链接紧前方、最迟 2 秒前更改条件，也可能不会对该链接产生影响，需要注意。

所谓“最长 2 秒”，是指根据情况有时会比这更短。如果 CPU 有余力、能够充分解码，大致会保持 2 秒，但如果 CPU 被其他处理占用、解码延迟，就会低于 2 秒。



另外，关于标签，标签事件是在实际的“播放位置”到达该位置时触发的，而与此相对，标签的“表达式”是在“解码位置”到达该位置时执行的，因此需要注意。

## 可读取的格式

循环调谐器目前可以处理以下 PCM 格式的文件。

- 无压缩 Wave (扩展名为 .wav)
- MS-ADPCM (扩展名为 .wav)
- Ogg Vorbis (扩展名为 .ogg)

循环调谐器使用与吉里吉里本体相同的插件。在标准分发配置下会自动检测各插件，因此不需要特别设置。

## 标签的表达式

通过给标签设置特殊格式的“表达式”，可以在通过该标签时对标志进行特殊处理。

在标签中记述“表达式”时，标签名的开头必须以 ':' (冒号) 开始。

表达式中依次排列着操作对象的标志、表示对该对象进行何种处理的“**运算符** (operator)”、作为运算符参数的“**操作数**”(部分运算符没有操作数)。

操作对象的标志通过在 '[' ']' (方括号) 中包围标志编号 (0~15) 来指定。操作数如果是数值，则直接记述数值；如果要指定其他标志，则通过在 '[' ']' (方括号) 中包围标志编号 (0~15) 来指定。

运算符有以下几种。

- **=**  
  将操作数的值赋给标志的值
- **+=**  
  将标志的值加上操作数的值
- **-=**  
  从标志的值减去操作数的值
- **++**  
  将标志的值增加 1
- **--**  
  将标志的值减少 1

无论哪种情况，标志的值的范围都必定为 0 ~ 9999。低于 0 时会被修正为 0，超过 9999 时会被修正为 9999。



例:

`:[0]=1    `将 1 赋值给第 0 号标志的值

`:[1]=[0]  `将第 0 号标志的值赋值给第 1 号标志的值

`:[1]+=3   `将第 1 号标志的值加上 3

`:[0]++    `将第 1 号标志的值增加 1

> **Note:**
> 多个标签位于同一位置时，执行顺序是不确定的。

## 提示与 Tips

- **链接的调整**  
  在由链接造成的 PCM 接缝处，如果调整得不好，就会产生爆裂噪声。虽然可以使用“使链接平滑” (平滑链接) 功能来减轻这种爆裂噪声，但建议首先在不使用平滑链接的情况下进行调整。
  
  
  
  如果是用音源 + 音序器等电子环境生成的音乐，多数情况下可以像下图那样，找到链接前后基本一致的点。
  
  ![](../_assets/lt_link_tuner_wave_match.png)
  
  
  
  此外，即使出现噪声是没办法的事，也有以下这些使其不明显的要点。
  
  - 作为接缝的位置，选在军鼓或镲片类鼓点的紧前方作为循环的接缝，噪声会不显眼。高音、破裂音等的紧前方也很合适
  - 作为接缝的位置，选在交叉点时噪声会不显眼
- **通过条件链接控制乐曲进行**  
  从前奏开始进入循环，随着游戏等的进行，在某个条件下跳出循环并进入另一个循环——这种反映游戏进程与情境的乐曲进行控制，可以通过条件链接与标志的操作来实现。
  
  不过，当然，链接只会在循环调谐器中预先指定的位置起作用。也就是说，即使更改链接的条件，如果没有到达链接的位置，播放位置也不会改变。
  
  如果循环较长等情况下，必须到达循环终点才能跳出循环会成为问题，那么就必须在乐曲结构上下功夫，使循环途中也能跳出循环。
  
  例如，像下图这样。
  
  
  
  ![](../_assets/lt_complex_loop.png)
  
  
  播放开始时，标志 0 为 0。播放“前奏”后，“循环”部分会被反复播放。
  
  此时，随着游戏等推进，当标志 0 变为 1 后，就会在 (1) 或 (2) 的时机跳出这个“循环”。
  
  如果在 (1) 处跳出循环，则会经过“(1)→(3) 迁移”播放到 (3)，然后播放“剩余部分”。
  
  另外，如果在 (2) 处跳出循环，则会经过“(2)→(3) 迁移”后，通过链接跳转到 (3)，然后播放“剩余部分”。
  
  
  
  应该可以有各种各样的应用。
