## 模式 { #mode }

| 类型 | 说明 |
| --- | --- |
| 视频叠加模式 (vomOverlay) | 在画面最前面 (全屏) 显示视频的默认模式。显示在比任何其他图层都靠前的位置。<br>在 WINVER 中，影像会合成到绘制设备 (BasicDrawDevice) 的 Direct3D 11 后台缓冲区。<br>最适合单纯播放并停止视频的用途，负载也较轻。不进行追加图像的合成 (需要时请使用混合模式)。<br>为兼容起见，常量 vomMFEVR 作为 vomOverlay 的别名保留。 |
| 图层模式 (vomLayer) | 把视频解码到指定图层进行播放的模式。<br>环境依赖性低，可使用指定帧间的循环 (区间循环) 与指定帧处的处理 (Period 事件) 等功能。<br>不过存在 CPU 负载比其他模式更高的缺点。 |
| 混合模式 (vomMixer) | 在叠加的基础上，还能把 `setMixingLayer` 指定的图层图像合成到视频上的模式。<br>为了可靠地合成追加图像，这种用途不使用硬件解码，必定走软件合成路径。 |

## 支持的格式与解码器 { #codec }

在 WINVER 中，根据扩展名与容器使用以下解码器。

| 格式 | 解码器 | 备注 |
| --- | --- | --- |
| webm (VP8 / VP9) | movie-player | 支持带 Alpha 通道的 webm。 |
| mpg / mpeg (MPEG-1) | pl_mpeg | 支持多路音频流复用 (多音频)。 |
| wmv / asf / mp4 / mov / avi 等 | Media Foundation SourceReader | 在 CPU 侧解码为 BGRA (CPU 路径)。 |
| mp4 / wmv 等 (MF 原生) | IMFMediaEngine (HW 解码) | 默认进行硬件解码。指定 `-mediaengine=no` 会禁用它，并回退到 CPU 的 SourceReader。 |

由 IMFMediaEngine 进行的 HW 解码路径共享 BasicDrawDevice 的 Direct3D 11 设备。音频播放与 AV 同步由 MediaEngine 内部处理。

## 叠加合成的机制 { #overlay_compose }

叠加 (以及混合器) 的影像通过 pull 型的 VideoPresenter 传递给绘制设备。BasicDrawDevice 的 `Show` 每帧向 presenter 请求帧，并合成到后台缓冲区。

当切换到没有可接纳 presenter 的 host 的绘制设备时，会回退到使用子窗口的 Direct3D 11 present。

`System.captureScreen` 通过回读后台缓冲区获取画面，因此捕获的画面包含叠加影像。

## SDL(GENERIC) 中的视频播放 { #generic }

在 SDL(GENERIC) 系列中，webm 用 movie-player、MPEG-1 用 pl_mpeg 解码。

影像显示 (presenter) 有 SDL_Renderer 版与 OpenGL 版，OpenGL 版在着色器中执行 BT.601 的 YUV→RGB 转换。在 Emscripten(web) 中使用浏览器的 `<video>`。

视频的音频经 miniaudio 播放 (MovieAudioSink)。以已播放的采样数作为 AV 同步的主时钟，让影像侧跟随它。

## 特殊播放功能 { #trickplay }

| 类型 | 说明 |
| --- | --- |
| 区间循环 | 在指定的帧之间循环的功能。<br>要使用这个功能，必须预先在视频文件自身的循环返回目标帧上设置关键帧。<br>没有关键帧时，不会如预期那样循环。 |
| Period 事件 | 在指定的帧引发事件、从而进行某种处理的功能。<br>在事件发生时定位到相距较远的帧，可以跳过中间的帧，让视频看起来仿佛连在一起。<br>另外，想在视频同步显示字幕时，也可以在字幕的开始帧设置 Period 事件，等待事件后显示文字来实现。<br>此外，使用这个功能，还可以不让视频本身包含声音，而在指定帧用 SE 发声。 |
| 播放速度控制 | 可以指定视频的播放速度。<br>指定 1.0 为通常播放速度，0.5 为一半的播放速度，2 为 2 倍的播放速度。<br>可设置的范围取决于解码器/编解码器。 |
| 多音频 | MPEG-1 可以复用多条音频流，这是利用该特性的功能。<br>使用这个功能可以播放任意音频流。<br>例如，预先准备仅有 BGM、BGM+人声等音频流，让用户能够指定以哪种模式播放。<br>不过，音频流的切换有 2 秒左右的延迟，因此不太适合交互性强的用途。<br>可用于上述由用户选择、或根据场景改变视频音频之类的用途。 |

## 关于视频播放准备 (preparevideo) { #preparevideo }

preparevideo 把视频的第 1 帧绘制到指定的图层。

它用于防止非预期的图像 (内存中的垃圾数据或上一次的图像等) 显示在画面上。

也就是说，通过编写这样的处理：先把作为播放目标的图层设为不显示，用 openvideo 打开视频后调用 preparevideo，等待准备完成，准备完成后把播放目标图层设为显示状态，即可在显示时看到视频的第 1 帧。

另外，这个功能仅在图层模式下有意义。

## 关于图层模式下的图层指定 { #layermode }

在图层模式下播放视频时，使用 videolayer 指定绘制目标图层。

videolayer 可以指定 slot 与 channel、page、layer。

slot 用于在同时播放不同视频时，确定操作针对哪个视频。

几乎不会同时播放多个视频，因此通常省略写法，让其指定为 0 即可。

channel 用于指定输出到的图层。

1 个视频最多可以指定 2 个输出图层，因此用它来确定针对其中哪一个的指定。

之所以可以指定 2 个，是为了使用转场。

在视频播放中执行转场时，正面与背面的图层会互换，因此如果只输出到其中一方，视频就会变得不可见。

为避免这种情况，在视频播放中进行转场时，请把正面与背面的图层分别设置到通道 1 和 2。不进行转场的话，只指定正面即可。

## 视频结尾时的行为 { #end_of_video }

不指定循环播放视频时，播放到最后视频就会停止。

想保持显示视频最后一帧并推进游戏时，这种行为并不理想。

避免它的最简单方法是使用图层模式。

在图层模式下，视频是绘制到图层上的，因此最后一帧的图像会原样留在图层上。

因此，无需特别留意，就能保持显示最后一帧并推进游戏。

叠加或混合模式的情况下，停止后显示会消失，因此必须在到达最终帧之前暂停。

这可以通过 Period 事件实现，但如果真的设为最终帧，可能会有停止的风险，因此最好在视频末尾放入几帧虚拟帧，让稍微越过一点也不会出问题。

## 关于图层模式下视频不显示的现象 { #layer_alpha }

当作为视频播放目标的图层的显示类型为 Alpha 等时，会发生视频不显示的情况。

这是因为视频不带 Alpha 通道时，Alpha 通道的位置会被写入未定义数据。

图层显示类型为 Alpha 时，这些未定义数据会被当作 Alpha 值处理，有时会变得完全透明。

要避免这个问题，把播放目标图层的显示类型设为 opaque。

这样视频就能显示了。

## 混合播放 { #mixer_mode }

混合模式正如其名，可以实现把其他图层与视频混合后播放。

在混合模式中，与混合相关的可指定项有背景色、混合率和混合目标图层。

混合目标图层在与视频混合时，使用的是设置瞬间的图像。

因此，即使混合目标图层被更新，只要不重新设置，内容就不会更新。

不过，在每帧更新时调用该设置会让 CPU 负载变得相当高。

为了抑制 CPU 负载，设置时最好限定为仅在更新时进行。

背景色是在把混合率设为低于 1.0 时被混合的颜色。

把背景色设为黑色等并改变混合率，就可以实现淡入/淡出。

当然，也可以与混合目标图层之间进行淡入/淡出。

与混合目标图层的混合率和图层位置使用图层自身的信息。

也就是说，显示位置取决于图层的位置，混合率取决于图层的不透明度。

不过，由于与图层的混合按规格需要每次都进行指定，与图层进行淡入/淡出时 CPU 负载会变高。

## 关键帧与定位 { #seek_to_keyframe }

在吉里吉里Z 中，为了高速执行定位，把可定位的位置限定为关键帧。

指定非关键帧的帧时，会执行定位到距离指定帧最近的关键帧的处理。

不过，这个行为取决于 Codec，因此常常会出现非预期的行为。

因此，最好对要定位的帧务必设置关键帧。
